# Проектная работа: архитектура защиты данных ООО «Медикаменте»

Репозиторий содержит решение проектной работы по проектированию целевой архитектуры медицинского центра
«Медикаменте» с фокусом на работу с конфиденциальными данными (ПДн, врачебная тайна) и на переход
от ручных процессов и файлового ландшафта к единой платформе.

Сверка выполненного с формулировками задания — в [REQUIREMENTS.md](REQUIREMENTS.md).

## Структура репозитория

| Директория | Содержимое |
|---|---|
| [Task1](Task1/) | Анализ безопасности AS-IS: диаграммы потоков данных (DFD) по шести процессам, список проблемных зон, карта данных и мер защиты, механизм тегирования, доработанные диаграммы TO-BE |
| [Task2](Task2/) | Проектирование решения: диаграмма контекста C4 целевого состояния + диаграмма контейнеров MVP, описание новых блоков Privacy by Design и аналитического слоя |
| [Task3](Task3/) | Data Encryption at Rest and In Transit: классификация данных, обоснование защиты, инструменты, реестр программных и аппаратных средств, автоматизированный контроль |
| [Task4](Task4/) | Оценка узких мест при миграции: диаграмма Исикавы (draw.io) и отчёт с рекомендациями и приоритетами |
| [Task5](Task5/) | Cutover-план: обоснование стратегии миграции, поэтапный план, риски, роли, план отката |
| [Task6](Task6/) | Движок классификации данных: диаграмма C2, описание слоёв хранилища, метрики эффективности, масштабируемость |
| [tools](tools/) | Генераторы диаграмм и валидатор: все `.drawio` собираются из кода и воспроизводятся одной командой |

## Как воспроизвести диаграммы

Диаграммы не рисовались руками — они генерируются скриптами из [tools](tools/), поэтому результат
воспроизводим и проверяем. Нужен только Python 3.8+ без внешних зависимостей.

Пересобрать все диаграммы и проверить их корректность:

```bash
./tools/build.sh
```

Пересобрать вместе с PNG-превью (нужен установленный draw.io Desktop):

```bash
./tools/build.sh --with-png
```

Проверить диаграммы без пересборки (XML, дубли идентификаторов, связи в никуда):

```bash
python3 tools/validate.py
```

Проверить документы — относительные ссылки и разметку таблиц:

```bash
python3 tools/check_docs.py
```

Убедиться, что репозиторий соответствует коду — после пересборки изменений быть не должно:

```bash
./tools/build.sh && git diff --stat
```

Подробности и отдельные команды — в [tools/README.md](tools/README.md).

Все диаграммы — в формате `.drawio` (открываются в [app.diagrams.net](https://app.diagrams.net)
или в desktop-версии draw.io). Файлы многостраничные: каждый бизнес-процесс — отдельная страница
(вкладки внизу окна draw.io).

| [Task2/c4-context-to-be.drawio](Task2/c4-context-to-be.drawio) | 2 | C4 уровень 1 (контекст) и уровень 2 (контейнеры MVP) |

## Сквозные обозначения

- **Fx.y** — идентификатор потока данных на DFD (например, F4.6 — передача реестра анализов в лабораторию).
- **Rx.y** — идентификатор зоны риска / проблемы (например, R2.1). Полный список — в [Task1/problems.md](Task1/problems.md).
- **Cn** — мера защиты из каталога мер (например, C4 — токенизация в PII Vault). Каталог приведён
  на каждой странице `dfd-to-be.drawio` и в [Task1/data-protection-map.md](Task1/data-protection-map.md).
- **Kn** — класс данных из классификации (например, K1 — специальная категория ПДн). Классы описаны
  в [Task3/README.md](Task3/README.md).

## Нормативный контекст

Решение опирается на требования законодательства РФ: 152-ФЗ «О персональных данных»
(в том числе ст. 6, 9, 10, 18, 18.1, 19, 21), 323-ФЗ «Об основах охраны здоровья граждан» (ст. 13 —
врачебная тайна), ПП РФ № 1119 (уровни защищённости ИСПДн), приказ ФСТЭК России № 21,
приказ ФСБ России № 378 (применение СКЗИ), 98-ФЗ «О коммерческой тайне», 54-ФЗ (ККТ), 402-ФЗ (бухучёт).
